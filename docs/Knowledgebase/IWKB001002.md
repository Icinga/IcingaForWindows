# Icinga Knowledgebase - IWKB001002

## Short Message

```text
[UNKNOWN] Unable to map Custom-Variables without "-" or "/" prefix to external binary check "<BinaryName>" when "ifw-api" is inactive: <VariableList> (IWKB001002)
```

---

## Cause

An external binary or script inside `C:\ProgramData\IcingaForWindows\Binaries` was invoked **without** the `ifw-api` `CheckCommand` template (`macros.ifw_api_arguments` is absent), and one or more custom variables without a leading `-` or `/` CLI flag prefix (for example `vars.load_win_warn = "80%"` or `vars.warning = "10"`) were sent in `macros`.

Unlike PowerShell functions — whose parameter names and types can be introspected at runtime via `(Get-Command).Parameters` — arbitrary native executables (`.exe`, `.cmd`, `.bat`, `.com`) expose no machine-readable metadata describing whether a custom variable called `load_win_warn` maps to `-w`, `--warning`, `/w`, or a positional argument. Guessing CLI flag names could silently pass wrong thresholds or malformed arguments to the binary.

When `ifw-api` is inactive on a binary check, Icinga for Windows therefore only permits:
- Executing the binary **with zero custom variables**, or
- Passing custom variables that **explicitly start with `-` or `/`** (such as `vars."-w" = "80%"`).

---

## Solution

### Recommended: Import `ifw-api` on the Binary's `CheckCommand`

Configure a `CheckCommand` that imports `ifw-api`, sets `vars.ifw_api_command` to the executable filename inside `C:\ProgramData\IcingaForWindows\Binaries`, and maps your Icinga custom variables cleanly via `arguments`:

```icinga2
object CheckCommand "ifw-check-load" {
    import "ifw-api"

    vars.ifw_api_command = "check_load.exe"

    arguments = {
        "-w" = {
            value = "$load_win_warn$"
            order = 1
        }
        "-c" = {
            value = "$load_win_crit$"
            order = 2
        }
    }
}

apply Service "Windows Load" {
    check_command      = "ifw-check-load"
    vars.load_win_warn = "80%"
    vars.load_win_crit = "90%"
    assign where host.vars.os == "Windows"
}
```

In **Icinga Director**:
1. Open **Commands -> Commands** and select (or create) the binary `CheckCommand`.
2. Add `ifw-api` to **Imports**.
3. Define the CLI flags (such as `-w`, `-c`) under **Arguments**.
4. Set the custom property `ifw_api_command` to the binary filename (for example `check_load.exe`) and deploy.
